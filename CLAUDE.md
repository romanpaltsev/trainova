# CLAUDE.md — Дневник тренировок

## Проект

«Дневник тренировок» — адаптивное веб-приложение-дашборд для записи силовых и кардио-тренировок (зал, велосипед, бег, лыжи). Личный инструмент автора и учебный проект по Django; пользователи — автор и приглашённые друзья/родственники. Интерфейс на русском. Это pet-проект одного разработчика: простота и поддерживаемость важнее «энтерпрайзности».

Рабочее кодовое имя — **trainova** (репозиторий github.com/romanpaltsev/trainova); имя временное и до публичного запуска может смениться, поэтому в интерфейсе, письмах и текстах продукт называется «Дневник тренировок», а слово trainova в UI не используется.

## Стек (зафиксирован — не менять и не предлагать альтернатив)

- Python 3.12+, Django (актуальный стабильный релиз)
- Зависимости и окружение — uv: pyproject.toml + uv.lock (lock-файл коммитится), `uv sync` / `uv run`; pip напрямую не использовать, requirements.txt не заводить. Dockerfile ставит зависимости тоже через uv
- Серверный рендеринг: шаблоны Django + HTMX; Alpine.js для мелкого клиентского интерактива (таймер, модалки)
- Chart.js для графиков
- PostgreSQL, psycopg 3
- django-allauth для аутентификации
- Тесты: pytest + pytest-django + factory_boy. Линт/формат: ruff
- Docker Compose для разработки: web + postgres + mailpit
- Секреты через .env (django-environ); .env не коммитится, .env.example всегда актуален
- UI-основа — Bootstrap 5.3+ (без jQuery); поверх него свой `static/css/tokens.css` с фирменными цветами и переопределением переменных Bootstrap
- JS/CSS-библиотеки (Bootstrap, HTMX, Alpine, Chart.js) хранить локально в static/ (vendored), без CDN
- Tailwind, AdminLTE и другие UI-слои не использовать
- НЕ использовать: DRF, React/Vue/SPA, celery/redis

## Ключевые архитектурные решения

1. **Кастомный пользователь**: `accounts.User(AbstractUser)`, создан ДО первой миграции, `AUTH_USER_MODEL = "accounts.User"`.
2. **Auth-флоу (allauth)**: регистрация email+пароль, обязательное подтверждение email, вход по email (без username), восстановление/сброс/смена пароля. Без соцлогинов. Honeypot-защита от ботов на форме регистрации.
3. **Почта**: все SMTP-настройки из env; в dev — mailpit. Код не зависит от конкретного бэкенда почты.
4. **Модель данных** (приложение `workouts`):
   - `Sport`: name, category ∈ {strength, cardio}, owner (FK User, NULL = глобальный)
   - `Exercise`: name, muscle_group (необязательное), owner (FK User, NULL = глобальное)
   - `Workout`: user, sport, started_at (nullable — NULL = черновик: тренировка подготовлена заранее, время не идёт), duration_min (NULL = тренировка не записана: либо идёт, либо ещё не начата), note, rest_seconds (nullable — отдых между подходами для ЭТОЙ тренировки; NULL = значение по умолчанию из профиля `User.rest_seconds_default` (90 сек); изменение длительности отдыха на экране живого режима записывается сюда и действует до конца тренировки), current_exercise (nullable FK Exercise — выбранное вручную текущее упражнение живого режима); для силовых длительность считается живым режимом, для кардио вводится руками
   - **Три состояния тренировки выводятся из этих двух колонок, отдельного поля-статуса нет**: черновик (`started_at IS NULL`) → идёт (`started_at NOT NULL`, `duration_min IS NULL`) → записана (`duration_min NOT NULL`). Черновиков может быть сколько угодно (план на пн/ср/пт), идущая — не больше одной на пользователя: частичный `UniqueConstraint unique_live_workout_per_user`. Комбинация «записана, но не начиналась» запрещена `CheckConstraint finished_workout_is_started`, поэтому `.finished()` гарантирует непустой `started_at` и `localtime(started_at)` в истории и агрегатах не может подставить `now()` вместо настоящей даты. `Meta.ordering` использует `nulls_last`: иначе Postgres поставил бы черновики в начало любой выборки без явной сортировки. Фильтровать только методами `Workout.objects.finished() / live() / planned() / unfinished()`
   - `StrengthSet`: workout, exercise, set_number, weight_kg (Decimal), reps, done (False = плановый подход живого режима; при завершении тренировки невыполненные удаляются — в завершённой тренировке остаются только выполненные)
   - `CardioDetails`: OneToOne(Workout), distance_km (Decimal), avg_heart_rate (nullable)
   - `ChangelogEntry`: kind ∈ {feature, fix}, title, body, published_at (редактируемая — можно ставить задним числом и отложенно), is_published — новости проекта («Что нового»); анонс пользовательской доработки едет вместе с ней одноразовой data-миграцией (`get_or_create` по заголовку, дата зашита) и пишется языком пользователя, а не разработчика; в `seed` — только стартовые записи для пустой базы; правит и снимает с публикации админ через Django admin; менеджер даёт `published()` и `unread_for(user)`; у `User` поле `changelog_seen_at` (NULL = ещё не открывал) — страница «Что нового» при открытии обновляет его, пункт в профиле показывает точку-бейдж, если есть опубликованные записи новее
5. **Гибридные справочники** (Sport, Exercise): записи с owner IS NULL — глобальные, правит только админ через Django admin; пользователь видит глобальные + свои: `Q(owner__isnull=True) | Q(owner=user)`. Уникальность имени — в пределах владельца (UniqueConstraint с учётом NULL).
6. **Изоляция данных — священное правило**: каждый queryset пользовательских данных фильтруется по request.user; чужая запись по прямому URL — 404. На каждую вьюху с данными — тест «пользователь А не видит данные Б».
7. **Никакой социальности**: пользователи не видят друг друга ни в каком виде.
8. **Живой режим и черновик — один экран и один URL** (`workout_live`): различие только в `started_at`, поэтому после кнопки «Начать тренировку» адрес не меняется и открытая вкладка остаётся рабочей. Черновик правится теми же эндпоинтами живого режима (добавить упражнение, степперы, убрать подход); запрещены только те действия, которые требуют идущего времени: «Подход выполнен» и «Завершить» отдают 404.

## UI-конвенции

- Один адаптивный дизайн, mobile-first: базовые стили под ~375px, брейкпоинты (min-width) вверх до полноценной десктопной сетки дашборда.
- Главный сценарий — телефон в спортзале: тач-таргеты ≥ 44px, крупные кнопки шага веса, `inputmode="decimal"/"numeric"` на числовых полях, минимум набора с клавиатуры.
- **Темы**: светлая и тёмная через color modes Bootstrap — атрибут `data-bs-theme` на `<html>`. Фирменные цвета — CSS custom properties в `static/css/tokens.css`, определённые для обеих тем (через переменные Bootstrap или свои `--app-*`-токены). Хардкод цветов в стилях и шаблонах запрещён — только переменные. Переключатель в шапке; дефолт — prefers-color-scheme; выбор — в localStorage; анти-FOUC-скрипт инлайном в `<head>`.
- Каждая страница обязана корректно выглядеть в обеих темах и на 375px/1440px.
- PWA: manifest.json + иконки + theme-color. Service worker НЕ делать (офлайн вне скоупа).
- Русский интерфейс; единицы: кг, км, мин. `TIME_ZONE = "Europe/Moscow"`, `USE_TZ = True`.

## Дизайн (эталон утверждён 25.08.2026)

- Визуальный эталон — макеты семи экранов (дашборд моб. и десктоп, живой режим, кардио-форма, история, профиль, «что нового»); PNG-экспорты лежат в `docs/design/`. Верстать по ним: компоновка, плотность, скругления, иерархия текста.
- Тёмная тема — основная (как в макетах); светлая строится из тех же ролей токенов, ниже даны оба набора. Bootstrap-переменные (`--bs-body-bg`, `--bs-body-color` и т.п.) переопределяются из tokens.css под оба значения `data-bs-theme`.
- **Шрифты** (Google Fonts, woff2-файлы хранить локально в `static/fonts/`): Unbounded 600/700 — крупные числа и таймеры (утилитарный класс `.num`); Manrope 400–800 — весь остальной текст. Fallback: `system-ui, sans-serif`.
- **Токены тёмной темы** (из макетов): фон `#0D1015`; карточка `#151A21`; приподнятая поверхность `#1B222B`; линия `rgba(255,255,255,.08)`; текст `#EDF1F7`, вторичный `#9AA5B5`, приглушённый `#77828F`; акцент `#C6F13E` (текст на акценте `#141A08`); успех/положительная дельта `#0ca30c`.
- **Токены светлой темы** (те же роли): фон `#F6F7F9`; карточка `#FFFFFF`; линия `rgba(15,23,32,.10)`; текст `#16202B`, вторичный `#5A6675`, приглушённый `#8A95A5`; акцент тот же `#C6F13E` с текстом `#141A08`; успех `#006300`.
- **Цвета видов спорта** (серии графиков; цвет закреплён за видом спорта, а не за порядком в наборе): тёмная тема — Силовая `#3987e5`, Велосипед `#d95926`, Бег `#199e70`, Лыжи `#c98500`; светлая — `#2a78d6` / `#eb6834` / `#1baf7a` / `#eda100`. Наборы проверены на различимость при дальтонизме на своих поверхностях. В графиках всегда легенда; числа и подписи — цветом текста, никогда цветом серии.
- **Правила графиков** (Chart.js настраивать под них): stacked bar с зазором 2px между сегментами и скруглённым верхом; тонкая сетка, подписи осей ≥11px приглушённым цветом; одна ось Y, без двойных осей; главный график дашборда — часы по неделям с разбивкой по видам спорта.
- **Прочее**: радиусы — карточки 16px, поля 12px, чипы/круглые кнопки pill (999px); иконки — только инлайн-SVG stroke 2px (никаких emoji в UI); у каждого вида спорта цветовая точка-маркер рядом с названием.

## Вне скоупа v1 — не делать и не предлагать «на вырост»

Соцфункции (лента, сравнение пользователей), импорт из Strava/Garmin/часов, многонедельные программы тренировок (циклы, переиспользуемые шаблоны «День A/B», отчёт «план vs факт»); подготовить одну конкретную тренировку заранее — можно и уже сделано, а вот программа на недели вперёд — нет. Настраиваемые виджеты дашборда, офлайн-режим/service worker, REST API, аналитика по группам мышц, соцлогины, мультиязычность, ник и загрузка аватарки (в v1 аватар — первая буква email, никаких файловых аплоадов и MEDIA).

## Рабочий процесс

- Автор учится Django: при нетривиальных решениях коротко объясняй «почему так» (1–3 предложения, без лекций).
- Одна фича за раз; после каждого этапа приложение в работающем состоянии.
- Тесты обязательны для: изоляции данных, гибридных справочников, подстановки весов из прошлой тренировки, агрегаций дашборда.
- После вёрстки каждого экрана — скриншот через Playwright в 375px и 1440px в обеих темах; посмотри на него сам, сверь с `docs/design/` и поправь расхождения до сдачи этапа.
- Миграции всегда коммитятся; `ruff check` и `ruff format` перед коммитом.
- Коммиты небольшие, сообщения на русском.
